Problem and contract

top is a count in [0,cap]. Reject invalid state before access; push fails when full and pop when empty. Return 1 only for a completed operation.

C interface

CODE
int algorithm_array_backed_stack(int32_t *a, uint32_t cap, uint32_t *top, int push, int32_t *value);

Register map

FunctionArgumentEntry location
algorithm_array_backed_stackint32_t *aR0
algorithm_array_backed_stackuint32_t capR1
algorithm_array_backed_stackuint32_t *topR2
algorithm_array_backed_stackint pushR3
algorithm_array_backed_stackint32_t *value[entry SP]

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Reject invalid/full/empty state.
  2. Push at top then increment.
  3. Pop by decrement then load.

Worked trace

Push 4 then 5; pop returns 5 and decrements top.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/*
 * Exam-study reference: Array-backed stack.
 * Recognition cue: bounded LIFO push pop.
 *
 * Contract rules:
 * - Fixed-width types make width and signedness part of the interface.
 * - A pointer never carries its length; count/capacity arguments are explicit.
 * - const input objects are not mutated. Non-const outputs may be changed only
 *   within their documented bounds.
 * - Invalid, empty, duplicate and arithmetic-limit behavior is executable in
 *   pattern_edge_vectors() and described in the adjacent README.
 *
 * Trace the validation step first, then the main loop/recurrence invariant,
 * then the final result or capacity check. Public suffix functions are named
 * variants of the same advertised pattern, not unrelated shortcuts.
 */

/* Primary algorithm and its named variants. */
int algorithm_array_backed_stack(int32_t *a, uint32_t cap, uint32_t *top, int push,
                                 int32_t *value) {
  if (!a || !top || !value || *top > cap)
    return 0;
  if (push) {
    if (*top >= cap)
      return 0;
    a[(*top)++] = *value;
  } else {
    if (!*top)
      return 0;
    *value = a[--*top];
  }
  return 1;
}

static int pattern_core_vector(void) {
  int32_t a[2], v = 7, o = 0;
  uint32_t top = 0;
  return algorithm_array_backed_stack(a, 2, &top, 1, &v) &&
         algorithm_array_backed_stack(a, 2, &top, 0, &o) && o == 7;
}
static int pattern_edge_vectors(void) {
  int32_t guarded[1] = {7}, v_bad = 9;
  uint32_t top_bad = 2;
  if (algorithm_array_backed_stack(guarded, 1, &top_bad, 0, &v_bad) || v_bad != 9)
    return 0;
  int32_t a[1], v = 1, o = 0;
  uint32_t top = 0;
  return !algorithm_array_backed_stack(a, 1, &top, 0, &o) &&
         algorithm_array_backed_stack(a, 1, &top, 1, &v) &&
         !algorithm_array_backed_stack(a, 1, &top, 1, &v) &&
         algorithm_array_backed_stack(a, 1, &top, 0, &o) && o == 1;
}
int pattern_test_suite(void) {
  if (!pattern_core_vector())
    return __LINE__;
  if (!pattern_edge_vectors())
    return __LINE__;
  return 0;
}
int test_main(void) { return pattern_test_suite(); }

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.

Complete projects and worked method

How to recognize it

Bounded last-in-first-out storage.

When not to use it

Not interchangeable with a FIFO queue.

Inputs and outputs

Keep capacity separate from top and define failure status.

Solving method

TEXT
1. Top counts stored items
2. check before push
3. decrement before pop
4. never read empty

Worked trace

push1,push2,pop ->2 then1.

C approach

Make the contract explicit in types and parameters. Keep capacity separate from top and define failure status.

Assembly considerations

Map this contract to registers, memory widths, and the frame before translating the steps. Not interchangeable with a FIFO queue.

Boundary tests
