Problem and contract

Primary tests primality; factorize emits ascending prime factors and returns total count even when capacity truncates writes. Zero and one have no factors.

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Reject values below two.
  2. Handle two/even values.
  3. Try odd divisors through n/divisor.
  4. Repeatedly divide to factorize.

Worked trace

36 -> factors 2,2,3,3; count 4.

#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/*
 * Exam-study reference: Prime testing and trial factorization.
 * Recognition cue: test prime using divisors through square root.
 *
 * Contract rules:
 * - Fixed-width types make width and signedness part of the interface.
 * - A pointer never carries its length; count/capacity arguments are explicit.
 * - const input objects are not mutated. Non-const outputs may be changed only
 *   within their documented bounds.
 * - Invalid, empty, duplicate and arithmetic-limit behavior is executable in
 *   pattern_edge_vectors() and described in the adjacent README.
 *
 * Trace the validation step first, then the main loop/recurrence invariant,
 * then the final result or capacity check. Public suffix functions are named
 * variants of the same advertised pattern, not unrelated shortcuts.
 */

/* Primary algorithm and its named variants. */

int algorithm_prime_testing_and_trial_factorization(uint32_t value) {
  uint32_t divisor;

  if (value < 2u) {
    return 0;
  }
  if ((value & 1u) == 0u) {
    return value == 2u;
  }
  for (divisor = 3u; divisor <= value / divisor; divisor += 2u) {
    if ((value % divisor) == 0u) {
      return 0;
    }
  }
  return 1;
}

uint32_t algorithm_prime_testing_and_trial_factorization_factorize(uint32_t value,
                                                                   uint32_t *factors,
                                                                   uint32_t capacity) {
  uint32_t divisor = 2u;
  uint32_t count = 0u;

  if ((factors == NULL) && (capacity != 0u)) {
    return 0u;
  }
  while ((value > 1u) && (divisor <= value / divisor)) {
    while ((value % divisor) == 0u) {
      if (count < capacity) {
        factors[count] = divisor;
      }
      ++count;
      value /= divisor;
    }
    divisor = (divisor == 2u) ? 3u : divisor + 2u;
  }
  if (value > 1u) {
    if (count < capacity) {
      factors[count] = value;
    }
    ++count;
  }
  return count;
}

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.

Complete projects and worked method

How to recognize it

Test/divide small positive integers.

When not to use it

Do not test divisor squared in a type that may overflow.

Inputs and outputs

Bound factor output capacity and choose trial step policy.

Solving method

TEXT
1. Handle n<2
2. try divisors while d<=n/d
3. divide factors repeatedly
4. emit residual

Worked trace

12 -> factor2 twice ->3 -> factors2,2,3.

C approach

Make the contract explicit in types and parameters. Bound factor output capacity and choose trial step policy.

Assembly considerations

Map this contract to registers, memory widths, and the frame before translating the steps. Do not test divisor squared in a type that may overflow.

Adaptation checklist

Bound factor output capacity and choose trial step policy.

Boundary tests

0,1,2; perfect square; prime; repeated factors.

Common mistakes
