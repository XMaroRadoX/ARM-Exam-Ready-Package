Component-label merge

Merge connectivity classes during edge processing

How to recognize it

Merge connectivity classes during edge processing.

When not to use it

Relabeling one endpoint does not merge the whole class.

Inputs and outputs

O(VE) relabeling differs from union-find complexity.

Solving method

TEXT
1. Initialize labels
2. for each joining edge replace old class throughout labels
3. count distinct classes

Worked trace

labels[0,1,2],edges0-1,1-2 -> [0,0,0].

C approach

Make the contract explicit in types and parameters. O(VE) relabeling differs from union-find complexity.

Assembly considerations

Map this contract to registers, memory widths, and the frame before translating the steps. Relabeling one endpoint does not merge the whole class.

Adaptation checklist

O(VE) relabeling differs from union-find complexity.

Boundary tests

self-edge; duplicate edge; disconnected classes.

Common mistakes

Relabeling one endpoint does not merge the whole class. Use the trace above to locate the first differing step.

 * Recognition cue: Kruskal component replacement and stacked arguments.

 * - Fixed-width types make width and signedness part of the interface.
 * - A pointer never carries its length; count/capacity arguments are explicit.
 * - const input objects are not mutated. Non-const outputs may be changed only
 *   within their documented bounds.
 * - Invalid, empty, duplicate and arithmetic-limit behavior is executable in
 *   pattern_edge_vectors() and described in the adjacent README.
 *
 * Trace the validation step first, then the main loop/recurrence invariant,
 * then the final result or capacity check. Public suffix functions are named
 * variants of the same advertised pattern, not unrelated shortcuts.
 */

uint32_t algorithm_algorithm_pat_alg_component_merge_001_assembly(uint32_t *label, uint32_t n, uint32_t from,
                                     uint32_t to, uint32_t limit);



static int pattern_core_vector(void) {
  uint32_t a[] = {1, 2, 1};
  return algorithm_algorithm_pat_alg_component_merge_001_assembly(a, 3, 1, 2, 3) == 2 && a[0] == 2 &&
         a[2] == 2;
}
static int pattern_edge_vectors(void) {
  uint32_t a[] = {1, 1};
  return algorithm_algorithm_pat_alg_component_merge_001_assembly(a, 2, 1, 2, 1) == 0 &&
         algorithm_algorithm_pat_alg_component_merge_001_assembly(NULL, 0, 1, 2, 0) == 0;
}
int pattern_test_suite(void) {
  if (!pattern_core_vector())
    return __LINE__;
  if (!pattern_edge_vectors())
    return __LINE__;
  return 0;
}
int test_main(void) { return pattern_test_suite(); }

#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/*
 * Exam-study reference: Component-label merge.
 * Recognition cue: Kruskal component replacement and stacked arguments.
 *
 * Contract rules:
 * - Fixed-width types make width and signedness part of the interface.
 * - A pointer never carries its length; count/capacity arguments are explicit.
 * - const input objects are not mutated. Non-const outputs may be changed only
 *   within their documented bounds.
 * - Invalid, empty, duplicate and arithmetic-limit behavior is executable in
 *   pattern_edge_vectors() and described in the adjacent README.
 *
 * Trace the validation step first, then the main loop/recurrence invariant,
 * then the final result or capacity check. Public suffix functions are named
 * variants of the same advertised pattern, not unrelated shortcuts.
 */

/* Primary algorithm and its named variants. */
uint32_t algorithm_algorithm_pat_alg_component_merge_001_c(uint32_t *label, uint32_t n, uint32_t from,
                                     uint32_t to, uint32_t limit) {
  uint32_t i, c = 0;
  if (!label || n > limit)
    return 0;
  for (i = 0; i < n; i++)
    if (label[i] == from) {
      label[i] = to;
      c++;
    }
  return c;
}
