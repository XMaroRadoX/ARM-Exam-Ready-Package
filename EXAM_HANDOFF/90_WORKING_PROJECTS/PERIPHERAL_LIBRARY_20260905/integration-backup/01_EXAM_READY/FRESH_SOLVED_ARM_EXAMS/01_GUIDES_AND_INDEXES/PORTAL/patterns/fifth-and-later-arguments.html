How to recognize it

Ordinary word arguments spill to caller stack.

When not to use it

Do not use entry offsets after allocating a frame.

Inputs and outputs

Recompute offsets after every save-set change.

Solving method

TEXT
1. Record entry SP
2. count frame bytes including padding
3. load fifth at newSP+frame
4. restore frame

Worked trace

PUSH two words -> fifth at SP+8.

C approach

Make the contract explicit in types and parameters. Recompute offsets after every save-set change.

Assembly considerations

Map this contract to registers, memory widths, and the frame before translating the steps. Do not use entry offsets after allocating a frame.

Adaptation checklist

Recompute offsets after every save-set change.

Boundary tests

different fifth/sixth values; changed prologue; alignment.

Common mistakes

Do not use entry offsets after allocating a frame. Use the trace above to locate the first differing step.

; Recommended exam template: access arguments 5-7 safely
; C prototype:
; uint32_t sum7(uint32_t a, uint32_t b, uint32_t c, uint32_t d,
;               uint32_t e, uint32_t f, uint32_t g);
; Arguments 1-4 are R0-R3. Arguments 5-7 are at the caller's original SP.
; Capture original SP before PUSH. Eight saved registers keep SP aligned.

                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB
                EXPORT  sum7

sum7            PROC
                MOV     R12, SP
                PUSH    {R4-R9, R12, LR}
                LDR     R4, [R12, #0]
                LDR     R5, [R12, #4]
                LDR     R6, [R12, #8]
                ADDS    R0, R0, R1
                ADDS    R0, R0, R2
                ADDS    R0, R0, R3
                ADDS    R0, R0, R4
                ADDS    R0, R0, R5
                ADDS    R0, R0, R6
                POP     {R4-R9, R12, PC}
                ENDP

                END
