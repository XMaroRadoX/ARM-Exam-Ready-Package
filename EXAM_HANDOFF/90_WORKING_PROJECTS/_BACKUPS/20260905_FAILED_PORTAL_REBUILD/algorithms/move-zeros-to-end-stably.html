Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named array_move_zeros_to_end to move zeros to the end stably. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Move every zero after all nonzero values while preserving nonzero order. Empty input succeeds; a null nonempty base fails.

C interface

CODE
int array_move_zeros_to_end(int32_t *values, uint32_t count)

Register map

FunctionArgumentEntry location
array_move_zeros_to_endint32_t *valuesR0
array_move_zeros_to_enduint32_t countR1

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Compact nonzero values at a write index.
  2. Fill the remaining suffix with zeros.
  3. Never read beyond count.

Worked trace

[0,4,0,-2,7] becomes [4,-2,7,0,0].

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Move zeros to the end stably
 * Contract: Move every zero after all nonzero values while preserving nonzero order.
 * Empty input succeeds; a null nonempty base fails. Method:
 * 1. Compact nonzero values at a write index.
 * 2. Fill the remaining suffix with zeros.
 * 3. Never read beyond count.
 */
int array_move_zeros_to_end(int32_t *values, uint32_t count) {
  if (!values && count)
    return 0;
  uint32_t write = 0;
  for (uint32_t read = 0; read < count; ++read)
    if (values[read] != 0)
      values[write++] = values[read];
  while (write < count)
    values[write++] = 0;
  return 1;
}

Common exam mistakes

  • Losing the original order when the prompt explicitly requires a stable transform.
  • Moving one element too far and reading or writing outside the array.
  • Modifying the array before every fallible precondition has passed.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
