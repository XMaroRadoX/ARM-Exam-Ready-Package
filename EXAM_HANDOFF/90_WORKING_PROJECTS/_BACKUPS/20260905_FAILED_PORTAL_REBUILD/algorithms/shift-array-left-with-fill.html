Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named array_shift_left to shift an array left with a fill value. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Shift by amount positions and fill vacated positions. An amount at least count fills the array. Empty input succeeds; null nonempty input fails.

C interface

CODE

Register map

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Validate storage.
  2. Clamp amount to count.
  3. Copy in the safe direction.
  4. Fill vacated positions.

Worked trace

[1,2,3,4] shifted left by 2 with -1 becomes [3,4,-1,-1].

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Shift an array left with a fill value
 * Contract: Shift by amount positions and fill vacated positions. An amount at least
 * count fills the array. Empty input succeeds; null nonempty input fails. Method:
 * 1. Validate storage.
 * 2. Clamp amount to count.
 * 3. Copy in the safe direction.
 * 4. Fill vacated positions.
 */
int array_shift_left(int32_t *values, uint32_t count, uint32_t amount,
                     int32_t fill_value) {
  if (!values && count)
    return 0;
  if (amount > count)
    amount = count;
  for (uint32_t i = 0; i < count - amount; ++i)
    values[i] = values[i + amount];
  for (uint32_t i = count - amount; i < count; ++i)
    values[i] = fill_value;
  return 1;
}

Common exam mistakes

  • Losing the original order when the prompt explicitly requires a stable transform.
  • Moving one element too far and reading or writing outside the array.
  • Modifying the array before every fallible precondition has passed.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
