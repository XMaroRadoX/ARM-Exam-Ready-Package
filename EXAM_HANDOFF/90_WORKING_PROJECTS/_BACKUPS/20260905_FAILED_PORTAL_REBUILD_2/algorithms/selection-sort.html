Problem and contract

In-place ascending signed-word selection sort, not stable. Null input is a no-op.

C interface

CODE
void algorithm_selection_sort(int32_t *a, uint32_t n);

Register map

FunctionArgumentEntry location
algorithm_selection_sortint32_t *aR0
algorithm_selection_sortuint32_t nR1

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. For each output position find the minimum remaining element.
  2. Swap once.

Worked trace

[3,1,2]: select 1, then 2 -> [1,2,3].

/*
 * Exam-study reference: Selection sort.
 * Recognition cue: select minimum and swap.
 *
 * Contract rules:
 * - Fixed-width types make width and signedness part of the interface.
 * - A pointer never carries its length; count/capacity arguments are explicit.
 * - const input objects are not mutated. Non-const outputs may be changed only
 *   within their documented bounds.
 * - Invalid, empty, duplicate and arithmetic-limit behavior is executable in
 *   pattern_edge_vectors() and described in the adjacent README.
 *
 * Trace the validation step first, then the main loop/recurrence invariant,
 * then the final result or capacity check. Public suffix functions are named
 * variants of the same advertised pattern, not unrelated shortcuts.
 */

/* Primary algorithm and its named variants. */
void algorithm_selection_sort(int32_t *a, uint32_t n) {
  uint32_t i, j, m;
  if (!a)
    return;
  if (!a)
    return;
  for (i = 0; i < n; i++) {
    m = i;
    for (j = i + 1; j < n; j++)
      if (a[j] < a[m])
        m = j;
    if (m != i) {
      int32_t t = a[i];
      a[i] = a[m];
      a[m] = t;
    }
  }
}

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.

Complete projects and worked method

How to recognize it

Sort bytes/words in required ascending order.

When not to use it

Do not choose signed branches for unsigned keys.

Inputs and outputs

Choose load width and comparison signedness; use the unsigned comparison variant for high-bit unsigned keys.

Solving method

TEXT
1. Copy if input must survive
2. select the smallest remaining element
3. exchange it with the first unsorted position
4. repeat

Worked trace

[3,-1,2] -> [-1,3,2] -> [-1,2,3].

C approach

Make the contract explicit in types and parameters. Choose load width and comparison signedness; use the unsigned comparison variant for high-bit unsigned keys.

Assembly considerations

Map this contract to registers, memory widths, and the frame before translating the steps. Do not choose signed branches for unsigned keys.

Adaptation checklist

Choose load width and comparison signedness; use the unsigned comparison variant for high-bit unsigned keys.

Boundary tests

empty; one; equal; signed minimum; high-bit unsigned.

Common mistakes

Do not choose signed branches for unsigned keys. Use the trace above to locate the first differing step.

    for (j = i + 1; j < n; j++)
      if (a[j] < a[m])
        m = j;
    if (m != i) {
      uint32_t t = a[i];
      a[i] = a[m];
      a[m] = t;
    }
  }
}
