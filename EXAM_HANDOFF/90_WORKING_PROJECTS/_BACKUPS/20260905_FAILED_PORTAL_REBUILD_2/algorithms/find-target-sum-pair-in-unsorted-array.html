Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named array_pair_sum_unsorted to find a target-sum pair in a unsorted array. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Find two distinct indexes whose exact 64-bit sum equals target. Output pointers must be valid and distinct; failure writes nothing.

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Enumerate first indexes from low to high.
  2. Enumerate each later second index.
  3. Return the lexicographically first matching pair.

Worked trace

For [8,3,5,2] and target 10, the first pair is indexes 0 and 3.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Find a target-sum pair in a unsorted array
 * Contract: Find two distinct indexes whose exact 64-bit sum equals target. Output
 * pointers must be valid and distinct; failure writes nothing. Method:
 * 1. Enumerate first indexes from low to high.
 * 2. Enumerate each later second index.
 * 3. Return the lexicographically first matching pair.
 */
int array_pair_sum_unsorted(const int32_t *values, uint32_t count, int32_t target,
                            uint32_t *first_out, uint32_t *second_out) {
  if (!values || !first_out || !second_out || first_out == second_out)
    return 0;
  for (uint32_t first = 0; first < count; ++first)
    for (uint32_t second = first + 1; second < count; ++second)
      if ((int64_t)values[first] + values[second] == target) {
        *first_out = first;
        *second_out = second;
        return 1;
      }
  return 0;
}

Common exam mistakes

  • Returning a later valid answer instead of the deterministic first answer.
  • Adding signed values in 32 bits when the pair sum can overflow.
  • Changing output indexes while searching and then returning failure.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
