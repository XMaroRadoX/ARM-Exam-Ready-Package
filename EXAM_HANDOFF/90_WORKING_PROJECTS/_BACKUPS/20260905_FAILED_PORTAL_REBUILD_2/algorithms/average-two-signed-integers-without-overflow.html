Average two signed integers without overflow

Return (left+right)/2 with C signed-division semantics: truncate toward zero. The addition is formed as a signed 64-bit value, so opposite and extreme inputs cannot overflow.

Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named average_two_i32 to average two signed integers without overflow. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Return (left+right)/2 with C signed-division semantics: truncate toward zero. The addition is formed as a signed 64-bit value, so opposite and extreme inputs cannot overflow.

C interface

CODE
int32_t average_two_i32(int32_t left, int32_t right)

Register map

FunctionArgumentEntry location
average_two_i32int32_t leftR0
average_two_i32int32_t rightR1

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Form the two-word signed sum.
  2. If a negative sum is odd, add one before shifting.
  3. Arithmetic-shift the 64-bit sum right once.

Worked trace

INT32_MIN and INT32_MAX sum to -1; truncating -1/2 toward zero returns 0.

        asr r2,r0,#31

        adds r0,r0,r1

Matching C

C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Average two signed integers without overflow
 * Contract: Return (left+right)/2 with C signed-division semantics: truncate toward
 * zero. The addition is formed as a signed 64-bit value, so opposite and extreme inputs
 * cannot overflow. Method:
 * 1. Form the two-word signed sum.
 * 2. If a negative sum is odd, add one before shifting.
 * 3. Arithmetic-shift the 64-bit sum right once.
 */
int32_t average_two_i32(int32_t left, int32_t right) {
  return (int32_t)(((int64_t)left + right) / 2);
}

Common exam mistakes

  • Performing signed overflow first and trying to detect it afterward.
  • Forgetting that signed division truncates toward zero.
  • Writing an output before division-by-zero, range or overflow checks are complete.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
