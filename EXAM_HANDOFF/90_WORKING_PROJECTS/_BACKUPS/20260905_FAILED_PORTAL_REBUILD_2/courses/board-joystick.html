Understand the idea

The joystick exposes select/down/left/right/up. The API normalizes active-low inputs into pressed bits. A level stays true while held; a pressed edge is true only for a transition from unpressed to pressed.

The API supports all 8 directions as combinations of four direction bits, plus a separate centre SELECT press. Diagonals are UP | LEFT, UP | RIGHT, DOWN | LEFT, and DOWN | RIGHT (use the EXAM_JOY_ prefix for each flag). There are no separate diagonal constants and no four-direction restriction in the API. Both inputs must be activated by the board or simulator. Follow the exam question: implement four directions when it asks for four, and diagonals when required.

Test the current held-state mask for a diagonal; the two controls may become pressed in different samples, so requiring both pressed-edge bits together can miss it. A held-state test remains true while held; implement one-action or repeat behavior separately as required by the paper.

Store the previous sample. Compute edges from previous/current, process them, then update previous. Reinitializing previous to zero every loop makes a held direction look like a new press. Decide how simultaneous directions are handled and whether repeat while held is allowed by the paper.

Edge detection is not automatically debounce. Mechanical noise may need a stable-sample filter. Keep state changes and display updates explicit so select cannot also edit a digit after changing modes.

exam_joystick_released_edges(previous,current) returns directions that were held and are now released. It uses the same argument order as pressed_edges, masks to five valid bits, and stores no state. Save current as previous after both comparisons. The Joystick event state machine pattern includes a complete press/hold/release project without automatic repeat.

Worked example

Illustrative fragment unless explicitly marked as a complete project below. Read the contract and required placement before copying.

C
uint32_t current = exam_joystick_read();
uint32_t edges = exam_joystick_pressed_edges(previous,current);
previous = current;
if (edges & EXAM_JOY_LEFT) { /* one left-press action */ }

Execution trace

Samples 0,left,left,0,left → edges 0,left,0,0,left. Five samples contain two distinct presses.

Try it before the answer

How would a game that repeats a held direction after a delay differ?

Hint 1

Keep level information as well as edges.

Hint 2

Use a timer/counter for delay and repeat spacing.

Reveal the worked answer

On the initial edge act once and start a hold timer. While the level stays pressed, act after the specified initial delay and then at the specified repeat interval. On release clear the timer. Do not invent repeat behavior if the paper requires one action per press.

Common mistakes and symptoms

Using current instead of edges repeats every sample. Clearing previous too early loses transition information.

Checkpoint

Trace press, hold, release, and simultaneous inputs against a written policy.

Deeper explanation and source examples

Continue into the maintained reference chapter

Joystick bits are normalized to one when pressed. Poll it periodically and compare two samples.

Show C code
C
uint32_t previous = 0u;
exam_joystick_init();
for (;;) {
  uint32_t current = exam_joystick_read();
  uint32_t pressed = exam_joystick_pressed_edges(previous, current);
  previous = current;
  if ((pressed & EXAM_JOY_SELECT) != 0u) exam_led_toggle(11u);
}

The five masks are EXAM_JOY_SELECT, DOWN, LEFT, RIGHT, and UP.
