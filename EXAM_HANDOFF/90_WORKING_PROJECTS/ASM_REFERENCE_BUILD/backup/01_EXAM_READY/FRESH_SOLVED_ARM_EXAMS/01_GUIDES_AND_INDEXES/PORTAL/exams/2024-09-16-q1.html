Inputs, outputs, constraints, and ownership

R0-R3 first four args; remaining three on caller stack

Constants: horizontal/vertical wall arrays

Components: Arrays, Graph, Maze, ABI, Stack arguments

Bounded solution method

  1. Write the exact prototype, handler names, constants, and ownership required by the paper.
  2. Use the exact paper interface, keep hardware ownership in C unless the question assigns it elsewhere, and keep the tested computation bounded.
  3. Trace the smallest valid input, the upper bound, duplicate or overflow behavior, and counter wraparound where applicable.
  4. Verify the C/assembly boundary: R0-R3, later stack words, preserved registers, stack alignment, and the return location.

; void kruskal(uint8_t *maze,uint8_t *horizontal,uint8_t *vertical,
;              uint32_t rows,uint32_t columns,uint32_t y,uint32_t x)
kruskal         PROC
                MOV     R12, SP
                PUSH    {R4-R11, LR}
                SUB     SP, SP, #4      ; aligned 40-byte frame
                LDR     R4, [R12]       ; columns (argument 5)
                LDR     R5, [R12, #4]   ; increment y
                LDR     R6, [R12, #8]   ; offset x
                MOV     R7, R0          ; maze
                MOV     R8, R1          ; horizontal walls
                MOV     R9, R2          ; vertical walls
                MUL     R10, R3, R4     ; total cells
kr_loop         ADD     R6, R6, R5
                CMP     R6, R10
                BHS     kr_vertical
                LDRB    R0, [R8, R6]
                CMP     R0, #0
                BNE     kr_h_wall
                ADDS    R5, R5, #1
                B       kr_check_done
kr_h_wall       CMP     R0, #1
                BNE     kr_check_done
                ADD     R11, R6, #1
                LDRB    R2, [R7, R6]
                LDRB    R3, [R7, R11]
                CMP     R2, R3
                BEQ     kr_check_done
                MOVS    R0, #0
                STRB    R0, [R8, R6]
                B       kr_merge
kr_vertical     SUB     R6, R6, R10
                CMP     R6, R10
                BHS     kr_check_done
                LDRB    R0, [R9, R6]
                CMP     R0, #0
                BNE     kr_v_wall
                ADDS    R5, R5, #1
                B       kr_check_done
kr_v_wall       CMP     R0, #1
                BNE     kr_check_done
                ADD     R11, R6, R4
                LDRB    R2, [R7, R6]
                LDRB    R3, [R7, R11]
                CMP     R2, R3
                BEQ     kr_check_done
                MOVS    R0, #0
                STRB    R0, [R9, R6]
kr_merge        CMP     R2, R3
                ITE     LO
                MOVLO   R0, R2          ; m
                MOVHS   R0, R3
                ITE     LO
                MOVLO   R1, R3          ; n
                MOVHS   R1, R2
                MOVS    R11, #0
kr_replace      CMP     R11, R10
                BHS     kr_check_done
                LDRB    R2, [R7, R11]
                CMP     R2, R1
                IT      EQ
                STRBEQ  R0, [R7, R11]
                ADDS    R11, R11, #1
                B       kr_replace
kr_check_done   MOVS    R11, #0
kr_nonzero      CMP     R11, R10
                BHS     kr_done
                LDRB    R0, [R7, R11]
                CMP     R0, #0
                BNE     kr_loop
                ADDS    R11, R11, #1
                B       kr_nonzero
kr_done         ADD     SP, SP, #4
                POP     {R4-R11, PC}
                ENDP
                END

Why the important lines are there

Initialization establishes one owner for every peripheral. Callback or IRQ code acknowledges and records only the event. Foreground code performs longer computation and output. Assembly code keeps its public ABI contract and never assumes hidden array lengths.

Complexity and memory

The algorithm tags are Arrays, Graph, Maze. Loop bounds and storage are fixed by the paper; no dynamic allocation is introduced.

Common wrong answers

  • Changing the required interface to an easier API call.
  • Using a Timer0-Timer2 API helper while that timer is student-owned.
  • Forgetting active-low input logic or write-one-to-clear interrupt acknowledgement.
  • Doing delays, sorting, filtering, or table generation inside an IRQ.
  • Reading the fifth argument at the wrong stack offset after pushing registers.
