Understand the idea

A translation unit is a C file after includes are processed. #include supplies declarations, not necessarily an implementation. Headers normally declare shared functions and extern objects rather than defining mutable global storage repeatedly.

File-scope static keeps a name private to that file. extern declares storage defined elsewhere. const prevents writes through that declaration. Header guards prevent repeated inclusion in one translation unit. Macros substitute text: parenthesize arguments and avoid side effects such as i++ in a macro that evaluates an argument twice.

Edit Source/sample.c and Source/ASM_funct.s for answers. Existing IRQ files may already define a required vector. Find and edit that owner in the working copy; adding a second handler in sample.c causes duplicate symbols. Do not remove whole driver groups simply to silence errors.

Worked example

Illustrative fragment unless explicitly marked as a complete project below. Read the contract and required placement before copying.

C
/* counter.h */
#ifndef COUNTER_H
#define COUNTER_H
#include <stdint.h>
extern uint32_t counter;
void increment(void);
#endif
/* counter.c: the single definition */
uint32_t counter = 0u;
void increment(void) { ++counter; }

Execution trace

Multiple files can include the declaration. Only counter.c allocates counter. The linker connects references to that definition.

Try it before the answer

Explain undefined symbol versus multiply defined symbol. Should a helper used only in sample.c be static?

Hint 1

One case has zero definitions; the other has multiple.

Hint 2

Limit visibility when sharing is unnecessary.

Reveal the worked answer

Undefined means an implementation is absent, excluded, or differently named. Multiply defined means several included files own the same symbol. A private helper should normally be static. Check project membership first.

Common mistakes and symptoms

An initialized global in a header creates multiple definitions. Renaming an IRQ handler prevents the vector from reaching it.

Checkpoint

Identify the one owner of each shared object and interrupt vector.

Deeper explanation and source examples

Continue into the maintained reference chapter

A declaration tells the compiler a name and type. A definition allocates the object or supplies the function body.

Show C code
C
static uint32_t next_value(uint32_t current); /* declaration */

static uint32_t counter;          /* zero-initialized definition */
static volatile uint32_t events;  /* shared with an interrupt */
static const uint16_t sine[4] = {512u, 800u, 512u, 224u};

static uint32_t next_value(uint32_t current)  /* definition */
{
  return current + 1u;
}

Use:

  • static at file scope for private state and helpers.
  • static volatile for private state written asynchronously by an ISR.
  • const for tables that must not change.
  • Static storage for large arrays; do not place a 1,000-word array on the

ordinary local stack.

  • One definition for a shared symbol and extern declarations elsewhere.

Do not put a normal initialized object definition in a header. Read Defining data for C/assembly objects, structures, alignment, padding and linker errors.
