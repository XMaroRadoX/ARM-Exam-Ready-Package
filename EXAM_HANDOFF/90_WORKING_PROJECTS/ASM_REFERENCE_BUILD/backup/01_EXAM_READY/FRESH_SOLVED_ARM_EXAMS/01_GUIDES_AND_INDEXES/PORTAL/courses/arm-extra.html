Before this lesson

9. Stack frames, nested calls, and preservation — finish its checkpoint first.

Understand the idea

For five ordinary 32-bit arguments, the fifth word is at entry SP. A prologue moves SP, so its offset relative to the new SP increases by the frame size. One option is to read it at a known corrected offset. Another is to remember entry SP before changing it, but a caller-clobbered register holding that address cannot be trusted across BL.

64-bit arguments and results introduce alignment and register-pair rules. Under AAPCS a doubleword argument is aligned to an even-numbered register pair; a following argument may consequently move to the stack. Structures and variadic calls require further rules. Do not extrapolate the ordinary four-word shortcut.

The paper's exact prototype is authoritative. Annotate argument words and stack locations before writing loads.

Worked example

Illustrative fragment unless explicitly marked as a complete project below. Read the contract and required placement before copying.

ASSEMBLY
; Five uint32_t arguments; fifth initially at [SP]
        PUSH {R4, LR}
        LDR R4, [SP, #8]
        ADD R0, R0, R4
        POP {R4, PC}

Execution trace

At entry fifth=S[0]. After saving two words SP=S-8; [SP+8] still addresses fifth. The function returns first+fifth.

Try it before the answer

Change the save set to R4-R7 and LR with an extra four-byte alignment slot. Where is the fifth argument now?

Hint 1

Five registers consume 20 bytes.

Hint 2

Include the padding in the total frame size.

Reveal the worked answer

After PUSH {R4-R7,LR} and SUB SP,SP,#4, the frame is 24 bytes. Fifth is [SP,#24]. Before returning ADD SP,SP,#4 then POP {R4-R7,PC}. Confirm alignment before any nested call.

Common mistakes and symptoms

A stale offset can read saved LR or another argument instead of the fifth. Saving entry SP in R12 is not safe across a callee.

Checkpoint

Recompute a stack argument offset after a prologue change.

Deeper explanation and source examples

Continue into the maintained reference chapter

At a public C/assembly call boundary, SP must be eight-byte aligned. Calculate the frame instead of guessing:

Show TEXT code
TEXT
saved registers bytes + local bytes + padding bytes = total SP change
total must preserve required alignment before every BL

The fifth argument starts at the caller's original [SP]. If the callee first pushes eight bytes, the fifth argument is now at [SP,#8]:

Show assembly code
ASM
; uint32_t sum5(uint32_t a, uint32_t b, uint32_t c,
;               uint32_t d, uint32_t e)
sum5            PROC
                PUSH    {R4,LR}       ; SP moved by 8
                LDR     R4, [SP,#8]   ; original caller SP + 0
                ADD     R0, R0, R1
                ADD     R0, R0, R2
                ADD     R0, R0, R3
                ADD     R0, R0, R4
                POP     {R4,PC}
                ENDP

If you later add saved registers or local storage, recalculate every incoming stack-argument offset. Do not copy the old offset unchanged.

Every exit must undo the same frame. Prefer one common epilogue for errors and early termination.
