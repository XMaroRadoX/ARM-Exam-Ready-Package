Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named string_delete_character to delete one character at an index. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Delete index, return the removed byte, and preserve NUL termination. Require index<length and text[length] to be NUL. Invalid input writes nothing.

C interface

CODE
int string_delete_character(uint8_t *text, uint32_t *length,
                            uint32_t index, uint8_t *removed_out)

Register map

string_delete_characteruint8_t *removed_outR3

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Validate and save the selected byte.
  2. Shift all later bytes including NUL left.
  3. Decrement length and publish the removed byte.

Worked trace

Delete index 1 from "AXRM" to return X and restore "ARM".

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Delete one character at an index
 * Contract: Delete index, return the removed byte, and preserve NUL termination.
 * Require index<length and text[length] to be NUL. Invalid input writes nothing.
 * Method:
 * 1. Validate and save the selected byte.
 * 2. Shift all later bytes including NUL left.
 * 3. Decrement length and publish the removed byte.
 */
int string_delete_character(uint8_t *text, uint32_t *length, uint32_t index,
                            uint8_t *removed_out) {
  if (!text || !length || !removed_out || index >= *length || text[*length] != 0)
    return 0;
  uint8_t removed = text[index];
  for (uint32_t i = index; i < *length; ++i)
    text[i] = text[i + 1];
  --*length;
  *removed_out = removed;
  return 1;
}

Common exam mistakes

  • Scanning beyond capacity when no NUL terminator is present.
  • Forgetting that required capacity includes the final NUL byte.
  • Applying ASCII case rules to punctuation or bytes outside A through Z and a through z.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
