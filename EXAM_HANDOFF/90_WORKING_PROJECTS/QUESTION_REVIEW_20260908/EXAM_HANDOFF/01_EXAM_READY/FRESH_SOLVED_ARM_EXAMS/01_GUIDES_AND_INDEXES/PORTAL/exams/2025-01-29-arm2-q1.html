Question · 2025-01-29 · ARM 2 Matrix Two Timers

Algorithms: Arithmetic · Bits · Matrix

Review complete within the stated contract and limitations

Exact contract

void bitMatrixMultiplication(const uint8_t *A, const uint8_t *B, uint8_t *C): R0=A, R1=B, R2=C. All are eight row bytes, MSB first. Write C=A*B over GF(2); preserve A and B. Q2’s explicit void prototype governs the return contract.

Original paper — page 1 · Original paper — page 2 · Original paper — page 3

Solution reasoning

  1. For each output row i and column j, XOR the eight products A[i, k]&B[k, j].
  2. Set bit 7-j of the output row from that parity, then store the completed byte.

Worked trace

  1. The paper’s A starts with 20, selecting row2 of B; therefore C[0]=3E.
  2. Complete expected C=[3E, 7B, 0B, C5, 79, EC, F3, 63].
  3. Multiplication by the MSB-first identity matrix returns the other matrix unchanged.

ASSEMBLY
                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB

                EXPORT  bitMatrixMultiplication

; void bitMatrixMultiplication(const uint8_t *A, const uint8_t *B, uint8_t *C)
bitMatrixMultiplication PROC
                PUSH    {R4-R11, R12, LR}
                MOV     R4, R0          ; A.
                MOV     R5, R1          ; B.
                MOV     R6, R2          ; C.
                MOVS    R7, #0          ; Row i.

matrix_row
                CMP     R7, #8
                BHS     matrix_done
                LDRB    R8, [R4, R7]
                MOVS    R9, #0          ; Result row.
                MOVS    R10, #0         ; Column j.

matrix_column
                CMP     R10, #8
                BHS     matrix_store_row
                MOVS    R12, #0         ; XOR sum for c(i,j).
                MOVS    R11, #0         ; k.

matrix_product
                CMP     R11, #8
                BHS     matrix_store_bit

                MOVS    R0, #0x80
                LSR     R0, R0, R11
                TST     R8, R0
                BEQ     matrix_next_k

                LDRB    R1, [R5, R11]
                MOVS    R2, #0x80
                LSR     R2, R2, R10
                TST     R1, R2
                BEQ     matrix_next_k

                MOVS    R0, #1
                EORS    R12, R12, R0

matrix_next_k
                ADDS    R11, R11, #1
                B       matrix_product

matrix_store_bit
                CMP     R12, #0
                BEQ     matrix_next_column
                MOVS    R0, #0x80
                LSR     R0, R0, R10
                ORRS    R9, R9, R0

matrix_next_column
                ADDS    R10, R10, #1
                B       matrix_column

matrix_store_row
                STRB    R9, [R6, R7]
                ADDS    R7, R7, #1
                B       matrix_row

matrix_done
                MOV     R0, R6
                POP     {R4-R11, R12, PC}
                ENDP

                LTORG
                ALIGN   4
                END

Code explanation

  • R8 retains one A row, R10 selects a B column, and R12 accumulates parity.
  • C is separate writable storage; no initial C contents are used.

Complexity and memory

8*8*8 bit products;40-byte saved-register frame.

Relevant mistakes

  • XORing matching row bytes is not matrix multiplication.
  • The phrase “returns C” does not require inventing a scalar return when the supplied C prototype is void.

Paper interpretation and limits

  • C must not overlap A or B. The source leaves the C pointer in R0 as a convenience, but callers must use the specified output array.

Review findings and corrections

  • Reviewed the original contract and current implementation; no additional implementation defect found within the documented domain.
