2023-02-07 Sort FreeRunning Timer — Q1

Copy signed bytes into byte storage, then sort ascending with insertion sort.

Question · 2023-02-07 · Sort FreeRunning Timer

Algorithms: Arrays · Sorting

ABI and memory: ABI

Review complete within the stated contract and limitations

Exact contract

void copyData(const int8_t *source, int8_t *destination, uint32_t length): R0=source, R1=destination, R2=byte count. void insertionSort(int8_t *values, uint32_t length): R0=array, R1=count. Both return void. Destination has at least length bytes; sorting changes only that destination.

Original paper — page 1

Solution reasoning

  1. Copy each byte without changing its bit pattern.
  2. For each index i starting at 1, retain the signed key, shift larger predecessors right, and insert the key into the gap.

Worked trace

  1. Copy [3,-14, 15,-92, 65, 35,-89]. The bytes are unchanged.
  2. Insert -14 before 3: [-14, 3, 15,-92, 65, 35,-89].
  3. Final signed order: [-92,-89,-14, 3, 15, 35, 65]. Empty and single-byte arrays need no shifts.

ASSEMBLY
                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB

                EXPORT  copyData
                EXPORT  insertionSort

; void copyData(const int8_t *source, int8_t *destination, uint32_t length)
copyData        PROC
                CMP     R2, #0
                BEQ     copy_done
copy_loop
                LDRB    R3, [R0], #1
                STRB    R3, [R1], #1
                SUBS    R2, R2, #1
                BNE     copy_loop
copy_done
                BX      LR
                ENDP

; void insertionSort(int8_t *values, uint32_t length)
; Signed byte loads make negative values sort correctly.
insertionSort   PROC
                PUSH    {R4-R8, LR}
                MOV     R4, R0          ; Base address.
                MOV     R5, R1          ; Array length.
                CMP     R5, #1
                BLS     sort_done

                MOVS    R6, #1          ; i = 1.
sort_outer
                CMP     R6, R5
                BHS     sort_done

                LDRSB   R7, [R4, R6]    ; x = A[i].
                SUBS    R8, R6, #1      ; j = i - 1.

sort_inner
                CMP     R8, #0
                BLT     sort_insert
                LDRSB   R0, [R4, R8]
                CMP     R0, R7
                BLE     sort_insert

                ADDS    R1, R8, #1
                STRB    R0, [R4, R1]
                SUBS    R8, R8, #1
                B       sort_inner

sort_insert
                ADDS    R8, R8, #1
                STRB    R7, [R4, R8]
                ADDS    R6, R6, #1
                B       sort_outer

sort_done
                POP     {R4-R8, PC}
                ENDP

                LTORG
                ALIGN   4
                END

Code explanation

  • LDRB/STRB suffice for copying; LDRSB is essential for signed comparisons during sorting.
  • R4 holds the base, R6 the outer index, R7 the key, and R8 the signed predecessor index. Test j<0 before loading A[j].

Complexity and memory

Copy O(n); insertion sort O(n²) worst case, O(n) when sorted; constant extra space.

Relevant mistakes

  • LDRB in the comparison treats -14 as 242.
  • Scaling an index by four corrupts byte storage.
  • Moving equal keys is unnecessary; BLE stops at the right position.

Paper interpretation and limits

  • Separate source and destination regions are assumed; this is not a general overlapping-memory move.

Review findings and corrections

  • Reviewed the original contract and current implementation; no additional implementation defect found within the documented domain.
