Implement the shifted-XOR LCG and fill ten bytes from Reset_Handler.

Question · 2025-07-01 · ARM 2 LCG Rhythm

Algorithms: Arrays · Arithmetic · Recurrence

ABI and memory: ABI

Review complete within the stated contract and limitations

Exact contract

uint32_t LCGsequence(uint32_t previous, uint32_t a, uint32_t c, uint32_t s, uint32_t m): R0-R3=previous, a, c, s; entry[SP]=m. Return ((a*previous+c) XOR (previous>>s)) mod m, using a logical shift. Reset_Handler fills DIM 10 bytes from seed 6, a 157, c3, s3, m256.

Original paper — page 1

Solution reasoning

  1. Compute the shifted ORIGINAL previous value before overwriting it with the multiply/add.
  2. XOR, take the unsigned remainder, and use it as the next seed.
  3. Keep the standalone startup result array visible in memory.

Worked trace

  1. First:157*6+3=945;6>>3=0;945 mod 256=177.
  2. Second:157*177+3=27792;177>>3=22;27792 XOR22=27782;mod 256=134.
  3. Bytes:B1 86 21 44 BF 31 16 83 4A 6C.

Install the answer in the current template

  • Replace Source/ASM_funct.s with the complete assembly.s download shown below.
  • Keep the template vector table and its weak Reset_Handler. The supplied strong Reset_Handler replaces it at link time. Do not add another strong reset handler.
  • Use a copy of the clean template. The build verifier follows these placement and handler-ownership steps; it never edits the clean template.

Complete ARM assembly answer

Show complete assembly solution
Open raw Assembly file
ASSEMBLY
                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB

                EXPORT  LCGsequence

DIM             EQU     10

                AREA    LCG_TEST_DATA, DATA, READWRITE, NOINIT
; The template scatter file places this area in an UNINIT region.
lcg_test_values SPACE   DIM

                AREA    |.text|, CODE, READONLY

                EXPORT  Reset_Handler
Reset_Handler   PROC
                SUB     SP, SP, #8
                MOV     R4, #256
                STR     R4, [SP]
                LDR     R4, =lcg_test_values
                MOVS    R0, #6          ; Seed.
                MOVS    R5, #0

lcg_reset_loop
                MOVS    R1, #157
                MOVS    R2, #3
                MOVS    R3, #3
                BL      LCGsequence
                STRB    R0, [R4, R5]
                ADDS    R5, R5, #1
                CMP     R5, #DIM
                BLO     lcg_reset_loop

                ADD     SP, SP, #8
                B       lcg_finished
lcg_finished    B       lcg_finished
                ENDP

; uint32_t LCGsequence(previous, a, c, shift, modulus)
LCGsequence     PROC
                LDR     R12, [SP]       ; Fifth argument: modulus.
                LSR     R3, R0, R3      ; previous >> shift.
                MUL     R0, R0, R1
                ADDS    R0, R0, R2
                EORS    R0, R0, R3
                UDIV    R1, R0, R12
                MLS     R0, R1, R12, R0
                BX      LR
                ENDP

                LTORG
                ALIGN   4
                END

Code explanation

  • This leaf routine reads the fifth argument at entry SP before any frame is created.
  • The Q1 reset loop reserves aligned stack-argument space. Q2/Q3 use a function-only assembly file so normal C startup remains available.

Complexity and memory

Constant work per term;DIM output bytes.

Relevant mistakes

  • XORing with the loop index implements ARM1 instead.
  • Arithmetic right shift is incorrect for an unsigned previous value.

Paper interpretation and limits

  • m must be nonzero and the tested shift is3. The paper parameters avoid intermediate overflow; a wider-input mathematical generator would require a separate arithmetic contract.

Review findings and corrections

  • Separated the standalone 10-byte Reset_Handler example from the callable routine used by the C questions. Removed the incorrect 256-element claim.
