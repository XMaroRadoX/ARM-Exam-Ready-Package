Question · 2026-02-03 · ARM 2 RLE ADC

Algorithms: Decimal

Review complete within the stated contract and limitations

Exact contract

uint32_t run_length_encoding(uint32_t digits): R0=input unsigned decimal number, R0=encoded next number. Process consecutive runs from left to right and append digit then count. Runs have length<=9, and the paper guarantees the output and intermediate computations fit32 bits.

Original paper — page 2

Solution reasoning

  1. Extract decimal digits right to left into a local byte buffer.
  2. Walk the buffer backward, accumulating the length of each equal-digit run.
  3. Append two decimal components at each run boundary, then append the final run.

Worked trace

  1. 2222779 ->24 then 72 then 91 ->247291
  2. Input 0 is one zero digit: Look_and_Say(0)=10; run_length_encoding(0)=1, the numeric representation of 01.
  3. Input 111 gives 31 in look-and-say and 13 in RLE.

Complete ARM assembly answer

ASSEMBLY
                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB

                EXPORT  run_length_encoding

; uint32_t run_length_encoding(uint32_t digits)
run_length_encoding PROC
                PUSH    {R4-R10, LR}
                SUB     SP, SP, #16     ; Reversed decimal digits.
                MOV     R4, SP
                MOV     R5, R0
                MOVS    R6, #0          ; Number of digits.
                MOVS    R10, #10

extract_digits
                UDIV    R7, R5, R10
                MLS     R8, R7, R10, R5
                STRB    R8, [R4, R6]
                ADDS    R6, R6, #1
                MOV     R5, R7
                CMP     R5, #0
                BNE     extract_digits

                SUBS    R6, R6, #1
                LDRB    R7, [R4, R6]    ; Current digit.
                MOVS    R8, #1          ; Run length.
                MOVS    R9, #0          ; Result.

look_loop
                CMP     R6, #0
                BEQ     append_look_run
                SUBS    R6, R6, #1
                LDRB    R5, [R4, R6]
                CMP     R5, R7
                BNE     append_then_continue
                ADDS    R8, R8, #1
                B       look_loop

append_then_continue
                MUL     R9, R9, R10
                ADD     R9, R9, R7
                MUL     R9, R9, R10
                ADD     R9, R9, R8
                MOV     R7, R5
                MOVS    R8, #1
                B       look_loop

append_look_run
                MUL     R9, R9, R10
                ADD     R9, R9, R7
                MUL     R9, R9, R10
                ADD     R9, R9, R8
                MOV     R0, R9
                ADD     SP, SP, #16
                POP     {R4-R10, PC}
                ENDP

                LTORG
                ALIGN   4
                END

Code explanation

  • The 16-byte local buffer holds every digit of uint32_t.
  • R7 is the current digit, R8 its count, R9 the decimal result. The two multiplication-by 10 steps encode the specified component order.

Complexity and memory

O(d) for d<=10 digits;48-byte frame including the local buffer.

Relevant mistakes

  • Reversing the whole number loses leading zeros created from trailing zeros.
  • Counting equal digits globally merges distinct runs.
  • Forgetting the last append drops the final run.

Paper interpretation and limits

  • Inputs whose encoded output exceeds 32 bits are outside the stated assumptions. Leading zeroes are represented numerically, so encoding the single digit 0 yields 1 (the numeric value of 01).

Review findings and corrections

  • Reviewed the original contract and current implementation; no additional implementation defect found within the documented domain.
