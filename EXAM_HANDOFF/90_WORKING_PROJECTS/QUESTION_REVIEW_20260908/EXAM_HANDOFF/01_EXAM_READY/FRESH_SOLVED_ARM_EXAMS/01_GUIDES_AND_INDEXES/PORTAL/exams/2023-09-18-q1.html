Build the digit-addition series in memory and return the accumulated digit sum, returning zero on overflow.

Exam topics

Question · 2023-09-18 · DigitAddition Buttons

Algorithms: Arrays · Arithmetic · Decimal

Review complete within the stated contract and limitations

Exact contract

uint32_t digitSum(uint32_t a) returns its decimal digit sum. uint32_t digitaddition(uint32_t *area, uint32_t N) fills N words including area[0], then returns the sum of digits of ALL N stored terms. Return zero immediately if generating a term overflows uint32_t. Q1 also requires a 50-word area and a chosen initial value in Reset_Handler.

Original paper — page 1

Solution reasoning

  1. Compute digitSum of the initial term once.
  2. Generate next=current+digitSum(current); check carry before storing.
  3. After storing, compute and accumulate the NEW term’s digit sum.

Worked trace

  1. Seed 47, N5 stores [47, 58, 71, 79, 95].
  2. Digit sums are [11, 13, 8, 16, 14]; total=62.
  3. N1 returns 11 and leaves the seed alone. Seed 0xFFFFFFFF, N2 returns 0 before writing the second term.

Install the answer in the current template

  • Replace Source/ASM_funct.s with the complete assembly.s download shown below.
  • Keep the template vector table and its weak Reset_Handler. The supplied strong Reset_Handler replaces it at link time. Do not add another strong reset handler.
  • Use a copy of the clean template. The build verifier follows these placement and handler-ownership steps; it never edits the clean template.

Complete ARM assembly answer

ASSEMBLY
                AREA    |.text|, CODE, READONLY
                PRESERVE8
                THUMB
                EXPORT  digitSum
                EXPORT  digitaddition

; uint32_t digitSum(uint32_t a)
digitSum        PROC
                MOVS    R1, #0
                MOVS    R2, #10
ds_loop         CMP     R0, #0
                BEQ     ds_done
                UDIV    R3, R0, R2
                MLS     R12, R3, R2, R0
                ADD     R1, R1, R12
                MOV     R0, R3
                B       ds_loop
ds_done         MOV     R0, R1
                BX      LR
                ENDP

; uint32_t digitaddition(uint32_t *area, uint32_t count)
digitaddition   PROC
                PUSH    {R4-R8, LR}     ; 24-byte aligned non-leaf frame
                CMP     R1, #0
                BEQ     da_zero
                MOV     R4, R0
                MOV     R5, R1
                LDR     R6, [R4]        ; current term
                MOV     R0, R6
                BL      digitSum
                MOV     R7, R0          ; sum of all digits
                MOVS    R8, #1
da_loop         CMP     R8, R5
                BHS     da_done
                MOV     R0, R6
                BL      digitSum
                ADDS    R6, R6, R0
                BCS     da_zero
                STR     R6, [R4, R8, LSL #2]
                MOV     R0, R6
                BL      digitSum       ; count the NEW term, not its predecessor
                ADD     R7, R7, R0
                ADDS    R8, R8, #1
                B       da_loop
da_done         MOV     R0, R7
                POP     {R4-R8, PC}
da_zero         MOVS    R0, #0
                POP     {R4-R8, PC}
                ENDP

                AREA    DIGIT_SERIES, DATA, READWRITE, NOINIT
review_series   SPACE   200             ; 50 words, as requested
                AREA    |.text|, CODE, READONLY
                EXPORT  Reset_Handler
Reset_Handler   PROC
                LDR     R0, =review_series
                MOVS    R2, #47
                STR     R2, [R0]
                MOVS    R1, #50
                BL      digitaddition
review_finished B       review_finished
                ENDP
                LTORG
                END

Code explanation

  • R6 is the current term and R7 the accumulated digit sum.
  • ADDS followed immediately by BCS catches unsigned overflow. The corrected loop calls digitSum on the new term before adding to R7.

Complexity and memory

O(N*d) for at most ten decimal digits per word; constant call-frame space in addition to N output words.

Relevant mistakes

  • Adding the predecessor’s sum duplicates the seed and omits the final term.
  • Testing V instead of carry checks signed overflow, which is a different contract.

Paper interpretation and limits

  • The standalone Q1 startup example chooses47 and reserves50 words. Empty N returns 0 as an explicit safe extension.

Review findings and corrections

  • Fixed the sum to include each stored term exactly once, including the final term. Added the required standalone 50-word Reset_Handler example.
