I’m stuck

Build or linker errors
  • Save first; read the earliest meaningful error and its file/line.
  • Syntax/type error: inspect the statement and preceding brace/semicolon. Undefined symbol: check spelling, prototype, EXPORT, and project membership.
  • Multiply defined handler: find the existing owner and keep exactly one definition. Do not remove unrelated driver groups.
  • Rebuild the last known working milestone in your copy if needed; never reset the protected template to experiment.
Incorrect output
  • Check input arguments in the debugger before entering the routine.
  • Trace the first iteration that differs from a tiny expected example; check width, signedness, index scaling, bounds, and overflow.
  • Check the returned numeric value before LED encoding. Check physical LED4..LED11 mapping separately.
  • Retest the failing case and one previous passing case after the fix.
HardFault or a stuck exception
  • Pause and inspect the failing instruction and available fault/frame information.
  • Check whether the address is valid, aligned, and within the intended buffer; distinguish a value from a pointer.
  • Check SP balance, LR preservation, and any MSP/PSP frame selection.
  • Do not enable competing fault wrappers during the exam without reviewing existing ownership. Reduce the failing input.
Interrupt does not fire
  • Check initialization status and pin/clock configuration.
  • Timer/RIT need explicit start; successful SysTick configuration starts immediately.
  • Confirm vector spelling, one owner, interrupt enable/mask state, and peripheral interrupt mode.
  • Inspect pending hardware flags and the existing handler. Check that a different feature did not stop or reconfigure the source.
Repeated or missing button events
  • Separate raw IRQ count from confirmed press events.
  • Check debounce_begin in the one EINT owner and debounce_tick at the configured real interval.
  • Confirm event consumption, release/re-arm, and that the sampling timer remains active.
  • For joystick, retain previous level and distinguish edge detection from debounce and optional repeat.
Time running short
  • Stop expanding features; save the current working version.
  • Prioritize a correct buildable milestone for each question; avoid leaving one entirely untouched.
  • Keep the exact interface and meaningful partial behavior. Do not disguise temporary stubs as solved computation.
  • Reserve time for final build and collection-folder verification. Follow the actual paper's priorities, not a fixed historical schedule.
