Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named string_first_occurrence to find the first occurrence of a character. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Return a zero-based index, -1 when absent, or -2 for a null input, NUL target, zero capacity, or missing terminator. The complete bound is validated.

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Scan no farther than capacity.
  2. Stop only at NUL.
  3. Track the requested matching position.
  4. Distinguish not-found from invalid input.

Worked trace

For "BANANA" and A, the first index is 1.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Find the first occurrence of a character
 * Contract: Return a zero-based index, -1 when absent, or -2 for a null input, NUL
 * target, zero capacity, or missing terminator. The complete bound is validated.
 * Method:
 * 1. Scan no farther than capacity.
 * 2. Stop only at NUL.
 * 3. Track the requested matching position.
 * 4. Distinguish not-found from invalid input.
 */
int32_t string_first_occurrence(const uint8_t *text, uint32_t capacity,
                                uint8_t target) {
  if (!text || !target)
    return -2;
  uint32_t length = 0;
  while (length < capacity && text[length])
    ++length;
  if (length == capacity)
    return -2;
  int32_t found = -1;
  for (uint32_t i = 0; i < length; ++i)
    if (text[i] == target) {
      return (int32_t)i;
    }
  return found;
}

Common exam mistakes

  • Returning a later valid answer instead of the deterministic first answer.
  • Adding signed values in 32 bits when the pair sum can overflow.
  • Changing output indexes while searching and then returning failure.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
