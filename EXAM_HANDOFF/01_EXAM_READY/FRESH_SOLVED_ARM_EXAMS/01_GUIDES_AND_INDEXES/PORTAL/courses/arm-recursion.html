11. Wide arithmetic, fixed point, and recurrence state — finish its checkpoint first.

Understand the idea

Recursion means a function calls itself with a smaller or simpler subproblem. The base case must return without another call. Each live invocation needs its own preserved state, so recursion consumes stack proportional to depth.

For DFS, mark a node visited before exploring its neighbors. A depth bound must define what happens when exceeded; it cannot merely be a hopeful estimate. An explicit stack moves that resource limit into a visible array with a capacity check. Cycles require visited state even when recursion terminates on a tree.

On an embedded exam target, stack space is finite and shared with exceptions. Choose a bounded algorithm and explain worst-case storage instead of relying only on a small successful example.

Worked example

Illustrative fragment unless explicitly marked as a complete project below. Read the contract and required placement before copying.

ASSEMBLY
; Conceptual recursion, not a complete ARM function:
; factorial(n):
;   if n <= 1: return 1
;   preserve n and LR
;   result = factorial(n-1)
;   return n * result, restoring the frame

Execution trace

factorial(3) waits for factorial(2), which waits for factorial(1)=1; unwind gives 2 then 6. Three invocations exist at the deepest point.

Try it before the answer

State a uint32_t factorial input bound and compare an iterative version's storage with recursion.

Hint 1

13! exceeds an unsigned 32-bit result.

Hint 2

An iterative accumulator does not retain one frame per term.

Reveal the worked answer

Accept 0..12 for exact uint32_t factorial; reject or otherwise explicitly handle larger inputs. Iteration uses constant working storage; recursion uses depth-proportional frames. Test 0,1,12,13 and the error policy.

Common mistakes and symptoms

Missing base cases exhaust the stack. A graph cycle requires visited marking, not merely n-1 style reasoning.

Checkpoint

Bound depth, output range, and every explicit work buffer.

Deeper explanation and source examples

Continue into the maintained reference chapter

At a public C/assembly call boundary, SP must be eight-byte aligned. Calculate the frame instead of guessing:

Show TEXT code
TEXT
saved registers bytes + local bytes + padding bytes = total SP change
total must preserve required alignment before every BL

The fifth argument starts at the caller's original [SP]. If the callee first pushes eight bytes, the fifth argument is now at [SP,#8]:

Show assembly code
ASM
; uint32_t sum5(uint32_t a, uint32_t b, uint32_t c,
;               uint32_t d, uint32_t e)
sum5            PROC
                PUSH    {R4,LR}       ; SP moved by 8
                LDR     R4, [SP,#8]   ; original caller SP + 0
                ADD     R0, R0, R1
                ADD     R0, R0, R2
                ADD     R0, R0, R3
                ADD     R0, R0, R4
                POP     {R4,PC}
                ENDP

If you later add saved registers or local storage, recalculate every incoming stack-argument offset. Do not copy the old offset unchanged.

Every exit must undo the same frame. Prefer one common epilogue for errors and early termination.
