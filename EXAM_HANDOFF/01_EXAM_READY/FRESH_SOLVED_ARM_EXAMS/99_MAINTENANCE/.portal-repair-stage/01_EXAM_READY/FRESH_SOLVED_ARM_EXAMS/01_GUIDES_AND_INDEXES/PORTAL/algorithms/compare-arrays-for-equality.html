Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named arrays_equal to compare two arrays for equality. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Return 1 when all count signed words are equal. Empty arrays are equal even with null pointers. A null pointer with a nonzero count returns 0.

C interface

CODE
int arrays_equal(const int32_t *left, const int32_t *right, uint32_t count)

Register map

FunctionArgumentEntry location
arrays_equalconst int32_t *leftR0
arrays_equalconst int32_t *rightR1
arrays_equaluint32_t countR2

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Accept count zero immediately.
  2. Validate both bases.
  3. Stop on the first unequal pair.

Worked trace

[3,-1,8] equals [3,-1,8]; changing the final 8 to 7 makes it false.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Compare two arrays for equality
 * Contract: Return 1 when all count signed words are equal. Empty arrays are equal even
 * with null pointers. A null pointer with a nonzero count returns 0. Method:
 * 1. Accept count zero immediately.
 * 2. Validate both bases.
 * 3. Stop on the first unequal pair.
 */
int arrays_equal(const int32_t *left, const int32_t *right, uint32_t count) {
  if (count == 0)
    return 1;
  if (!left || !right)
    return 0;
  for (uint32_t i = 0; i < count; ++i)
    if (left[i] != right[i])
      return 0;
  return 1;
}

int test_main(void) {
  int32_t a[] = {3, -1, 8}, b[] = {3, -1, 8}, c[] = {3, -1, 7};
  CHECK(arrays_equal(a, b, 3));
  CHECK(!arrays_equal(a, c, 3));

  CHECK(!arrays_equal(0, b, 3));

}

Common exam mistakes

  • Using unsigned comparisons where the prompt requires signed ordering.
  • Returning the last match or difference when the contract requires the first one.
  • Reading one element beyond the supplied count while checking a neighbour or prefix.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
