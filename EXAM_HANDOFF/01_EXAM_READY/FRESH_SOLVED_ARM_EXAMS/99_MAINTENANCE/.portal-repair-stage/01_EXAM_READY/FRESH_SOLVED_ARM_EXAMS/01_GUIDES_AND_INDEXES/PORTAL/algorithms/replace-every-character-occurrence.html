Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named string_replace_character to replace every occurrence of a character. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Replace every old_character before NUL and return the replacement count. Both characters must be non-NUL. Invalid or unterminated input returns UINT32_MAX without modifying text.

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Validate the bounded length first.
  2. Scan exactly the characters before NUL.
  3. Replace matches and count them.

Worked trace

Replacing A with X in "BANANA" produces "BXNXNX" and returns 3.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Replace every occurrence of a character
 * Contract: Replace every old_character before NUL and return the replacement count.
 * Both characters must be non-NUL. Invalid or unterminated input returns UINT32_MAX
 * without modifying text. Method:
 * 1. Validate the bounded length first.
 * 2. Scan exactly the characters before NUL.
 * 3. Replace matches and count them.
 */
uint32_t string_replace_character(uint8_t *text, uint32_t capacity,
                                  uint8_t old_character, uint8_t new_character) {
  if (!text || !old_character || !new_character)
    return UINT32_MAX;
  uint32_t length = 0;
  while (length < capacity && text[length])
    ++length;
  if (length == capacity)
    return UINT32_MAX;
  uint32_t replaced = 0;
  for (uint32_t i = 0; i < length; ++i)
    if (text[i] == old_character) {
      text[i] = new_character;
      ++replaced;
    }
  return replaced;
}

}

Common exam mistakes

  • Losing the original order when the prompt explicitly requires a stable transform.
  • Moving one element too far and reading or writing outside the array.
  • Modifying the array before every fallible precondition has passed.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
