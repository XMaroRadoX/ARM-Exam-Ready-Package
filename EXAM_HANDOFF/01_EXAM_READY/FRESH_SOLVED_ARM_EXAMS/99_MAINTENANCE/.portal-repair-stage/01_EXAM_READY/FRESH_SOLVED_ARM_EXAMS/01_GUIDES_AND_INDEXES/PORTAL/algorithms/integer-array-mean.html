Integer array mean

Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named integer_array_mean to integer array mean. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Return the arithmetic mean truncated toward zero. Require 1..INT32_MAX elements and valid pointers. The 64-bit sum prevents intermediate 32-bit overflow; invalid input returns 0 without writing.

C interface

CODE
int integer_array_mean(const int32_t *values, uint32_t count, int32_t *mean_out)

Register map

FunctionArgumentEntry location
integer_array_meanconst int32_t *valuesR0
integer_array_meanuint32_t countR1
integer_array_meanint32_t *mean_outR2

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Accumulate an exact signed 64-bit sum.
  2. Divide the signed sum by the positive count.
  3. Store the quotient, which always fits int32_t.

Worked trace

For [-8,3,4], sum=-1 and -1/3 truncates toward zero to 0.

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Integer array mean
 * Contract: Return the arithmetic mean truncated toward zero. Require 1..INT32_MAX
 * elements and valid pointers. The 64-bit sum prevents intermediate 32-bit overflow;
 * invalid input returns 0 without writing. Method:
 * 1. Accumulate an exact signed 64-bit sum.
 * 2. Divide the signed sum by the positive count.
 * 3. Store the quotient, which always fits int32_t.
 */
int integer_array_mean(const int32_t *values, uint32_t count, int32_t *mean_out) {
  if (!values || !mean_out || count == 0 || count > INT32_MAX)
    return 0;
  int64_t sum = 0;
  for (uint32_t i = 0; i < count; ++i)
    sum += values[i];
  *mean_out = (int32_t)(sum / (int64_t)count);
  return 1;
}

Common exam mistakes

  • Dereferencing the data pointer before handling the documented empty-input case.
  • Using a result or accumulator width that is too small for the stated range.
  • Writing the output before every pointer, count and overflow condition has been validated.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
