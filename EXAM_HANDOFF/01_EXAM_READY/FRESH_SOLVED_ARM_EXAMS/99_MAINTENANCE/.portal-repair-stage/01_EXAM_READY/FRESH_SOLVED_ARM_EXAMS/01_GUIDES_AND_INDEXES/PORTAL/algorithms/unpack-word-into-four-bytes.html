Problem and contract

Exam question

Write a C function and matching ARMASM subroutine named unpack_four_bytes_be to unpack a 32-bit word into four bytes. Use the exact interface below, obey the stated failure behaviour, and preserve the AAPCS register and stack rules.

Write bits 31..24, 23..16, 15..8, and 7..0 into output[0..3]. Require capacity>=4 and a valid output; failure writes nothing.

C interface

CODE
int unpack_four_bytes_be(uint32_t value, uint8_t *output, uint32_t capacity)

Register map

FunctionArgumentEntry location

unpack_four_bytes_beuint32_t capacityR2

Stack locations above are measured at function entry. Add the bytes pushed or reserved by the prologue before loading a later argument. A word result returns in R0; a 64-bit integer returns low word in R0 and high word in R1. Modified R4–R11 registers must be restored, and SP must retain eight-byte alignment at a call.

How to solve it

  1. Validate all output storage.
  2. Shift each declared field to the low byte.
  3. Store exactly four bytes.

Worked trace

0x12345678 unpacks to bytes 12,34,56,78 hex.

        cmp r1,#0

Matching C

Show readable C reference
Open raw C file
C
#include <limits.h>
#include <stddef.h>
#include <stdint.h>
/* Exam prompt: Unpack a 32-bit word into four bytes
 * Contract: Write bits 31..24, 23..16, 15..8, and 7..0 into output[0..3]. Require
 * capacity>=4 and a valid output; failure writes nothing. Method:
 * 1. Validate all output storage.
 * 2. Shift each declared field to the low byte.
 * 3. Store exactly four bytes.
 */
int unpack_four_bytes_be(uint32_t value, uint8_t *output, uint32_t capacity) {
  if (!output || capacity < 4)
    return 0;
  output[0] = (uint8_t)(value >> 24);
  output[1] = (uint8_t)(value >> 16);
  output[2] = (uint8_t)(value >> 8);
  output[3] = (uint8_t)value;
  return 1;
}

Common exam mistakes

  • Allowing a bit index outside 0 through 31 or shifting by a full word width.
  • Using signed shifts when the task is defined on a uint32_t bit pattern.
  • Packing bytes in the opposite order from the stated most-significant-byte-first contract.

Adapting it in an exam

  • Keep the declared element width and signed comparisons together when changing the input type.
  • Distinguish a returned value, an index, a count and a status flag before changing the calling C code.
  • Check the stated storage, overlap, arithmetic and recursion limits before using a larger example.
  • For a nested BL call, preserve live arguments and the return address as shown in the implementation.
